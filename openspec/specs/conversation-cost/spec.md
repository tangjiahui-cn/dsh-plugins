# conversation-cost Specification

## Purpose

让用户在会话内看到此对话今日与累计的金额和 token、本机今天全部会话的总花费，以及账户余额；金额由真实 usage 按可配置单价换算。

## Requirements

### Requirement: 会话花费由已提交 usage 与配置单价派生

系统 MUST 从会话日志中已提交的 provider usage 计算 token 与金额：输入、输出、缓存读、缓存写分别计价，金额 = Σ(各桶 token × 该模型对应单价)。会话日志是唯一数据源，插件不在内存里累加独立计数。

#### Scenario: 一次模型调用结束后更新金额

- **WHEN** 会话提交一条带 usage 的 `assistant/message`
- **THEN** 弹窗的今日金额、累计金额与各桶 token 在无需刷新页面的情况下与该条 usage 一致

#### Scenario: 重试与失败调用计入

- **WHEN** 同一 step 先发生 `llm/retry-started` 再提交新的 `assistant/attempt` 或 `assistant/message`
- **THEN** 被替换的尝试按 DSH 的 tokenUsage 语义替换，不重复累加

#### Scenario: 模型缺少单价配置

- **WHEN** 该 step 的模型既不在 `prices` 也不在内置表
- **THEN** 金额位展示「—」，token 照常展示，不出现 0 元金额

### Requirement: 今日范围按配置时区的自然日计算

系统 MUST 用事件时间（`event.time`）与配置时区确定每个 token 桶属于哪一天，今日值只统计同一自然日内的事件；时区变化后按新时区重算。

#### Scenario: 跨零点

- **WHEN** 会话在本地 23:59 之后又提交一次调用
- **THEN** 这次调用的 token 计入新的一天，今日金额与累计金额分别反映该划分

#### Scenario: 修改时区配置

- **WHEN** 用户把时区从 `Asia/Shanghai` 改为 `UTC`
- **THEN** 今日金额与今日 token 按 `UTC` 日界重算，累计值不变

### Requirement: 胶囊展示此对话累计金额

会话标题行的胶囊 MUST 展示此对话的累计金额，不再展示今日金额或 token 总量；无数据时展示 `¥0.00`。

#### Scenario: 新会话无消耗

- **WHEN** 会话尚未提交任何调用
- **THEN** 胶囊展示 `¥0.00`，可点开弹窗

#### Scenario: 已有消耗

- **WHEN** 会话已经产生调用
- **THEN** 胶囊展示该会话从开始到现在的累计金额，金额为等宽数字

### Requirement: 弹窗展示此对话的两张卡片

点击胶囊 MUST 展开弹窗，第一张卡为「此对话今日总花费」、第二张为「此对话总花费」，每张卡展示金额与输入、输出、合计 token。两张卡 MUST 始终同时出现，不合并。

#### Scenario: 展开弹窗

- **WHEN** 用户点击胶囊
- **THEN** 弹窗按今日在上的顺序渲染两张卡，金额为卡片内最大字号

#### Scenario: 两卡数值相同时仍展示两张

- **WHEN** 今日金额与累计金额、token 总量都相同（会话尚未跨天）
- **THEN** 弹窗仍渲染两张卡片，不合并成一张

#### Scenario: 关闭弹窗

- **WHEN** 用户再次点击胶囊或按 `Escape`
- **THEN** 弹窗关闭，键盘焦点回到胶囊

### Requirement: 底栏展示本机今日总花费

弹窗底栏 MUST 展示「今日总花费」：本机当天全部会话（含子会话）的金额合计，由 Host 在弹窗展开时按需统计；统计期间显示加载态，失败显示「查询失败」与重试，不得显示 0。

#### Scenario: 展开时统计

- **WHEN** 用户展开弹窗
- **THEN** 底栏的今日总花费区域显示加载态，完成后显示当天金额

#### Scenario: 点击数值重新统计

- **WHEN** 用户点击底栏的今日总花费数值
- **THEN** 重新统计一次当天全部会话，期间该数值位置显示加载态

#### Scenario: 统计失败

- **WHEN** 会话日志读取失败或超时
- **THEN** 该区域显示「查询失败」与重试入口，不显示 0 元，另一张卡片与余额不受影响

### Requirement: 金额按时段的峰谷价换算

今日总花费的金额 MUST 按每个调用发生的时段取价：北京时间工作日 09:00–12:00、14:00–18:00 用标准价，其余时段用标准价的一半。此对话两张卡按标准价换算。

#### Scenario: 峰段与谷段分别计价

- **WHEN** 当天同时存在峰段与谷段的调用
- **THEN** 今日总花费等于两段分别计价的合计，而不是全部按标准价

### Requirement: 余额按需查询并允许失败

弹窗底栏 MUST 展示账户余额；查询中显示加载态，失败、未登录或超时时显示「查询失败」与重试，底栏行始终保留。余额数值 MUST 可点击重新查询。

#### Scenario: 余额查询成功

- **WHEN** 账户服务返回余额
- **THEN** 底栏显示该余额与币种

#### Scenario: 余额查询失败

- **WHEN** 账户服务超时或返回未登录
- **THEN** 显示「查询失败」与重试，不显示 0 元，其他区域不受影响

#### Scenario: 点击余额刷新

- **WHEN** 用户点击底栏的余额数值
- **THEN** 重新查询一次余额，期间该数值位置显示加载态

### Requirement: 开发与兼容性版本记录

插件包的 README MUST 记录开发与验证所用的 DeepSeek Harness 版本号，供升级排查使用。

#### Scenario: 升级排查

- **WHEN** 维护者查看插件 README
- **THEN** 能看到开发时验证过的 `@deepseek-ai/dsh` 版本号与安装形态
